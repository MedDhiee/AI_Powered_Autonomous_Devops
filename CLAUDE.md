# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A **DevOps Multi-Agent Orchestration System** that automatically analyzes software repositories and generates CI/CD pipelines, security assessments, deployment infrastructure, chaos experiments, and incident response playbooks. All agents use LLMs (OpenRouter, Groq, or Ollama) for enhanced analysis.

## Setup

```bash
# Install dependencies (run from workspace root: application/)
pip install -r shared/requirements.txt
pip install -r devops_multi_agents/requirements.txt

# Configure environment
cp .env.example .env
# Edit .env with your API keys and LLM provider settings
```

All scripts auto-load `.env` at startup — no need to export env vars manually.

## Common Commands

All commands must be run from the workspace root (`application/`).

### Run Full Workflow (Orchestrator)
```bash
python -m devops_multi_agents.run_workflow --repo <repo_path> --output-dir devops_multi_agents/outputs
python -m devops_multi_agents.run_workflow --repo gestion_stock --output-dir devops_multi_agents/outputs --include-llm --cicd-provider github
# With CI/CD push (human validation)
python -m devops_multi_agents.run_workflow --repo gestion_stock --output-dir devops_multi_agents/outputs --cicd-provider github --cicd-human-validation --push-cicd-pipelines
```

### Run Individual Agents
```bash
python -m devops_multi_agents.run_architecture_analysis gestion_stock --output devops_multi_agents/outputs/architecture-analysis.json --mermaid-output devops_multi_agents/outputs/architecture-diagram.mmd

python -m devops_multi_agents.agents.devsecops_security_agent --repo gestion_stock --arch devops_multi_agents/outputs/architecture-analysis.json --output devops_multi_agents/outputs/devsecops-security.json --strict-tools --skip-image-scan

python -m devops_multi_agents.agents.cicd_generation_agent --arch devops_multi_agents/outputs/architecture-analysis.json --provider github --output devops_multi_agents/outputs/cicd-generation.json

python -m devops_multi_agents.agents.deployment_agent --arch devops_multi_agents/outputs/architecture-analysis.json --cicd devops_multi_agents/outputs/cicd-generation.json --output devops_multi_agents/outputs/deployment-plan.json

# Simulation mode (fast, no real containers needed)
python -m devops_multi_agents.agents.chaos_engineering_agent --arch devops_multi_agents/outputs/architecture-analysis.json --output devops_multi_agents/outputs/chaos-experiments.json

# Docker mode (targets real running containers)
python -m devops_multi_agents.agents.chaos_engineering_agent --arch devops_multi_agents/outputs/architecture-analysis.json --output devops_multi_agents/outputs/chaos-experiments.json --backend docker --prometheus-url http://localhost:9090 --grafana-url http://localhost:3000 --container-map "hb_electronics=gestiondestock-ui,gestiondestock=gestiondestock-api"

python -m devops_multi_agents.agents.incident_response_agent --arch devops_multi_agents/outputs/architecture-analysis.json --security devops_multi_agents/outputs/devsecops-security.json --chaos devops_multi_agents/outputs/chaos-experiments.json --output devops_multi_agents/outputs/incident-response.json
```

### Model Benchmarking (LLM-as-Judge)
```bash
# Full workflow comparison between two models
python -m devops_multi_agents.run_llm_benchmark --repo gestion_stock --model-a z-ai/glm-4.5-air:free --model-b nvidia/nemotron-3-super-120b-a12b:free --judge-model z-ai/glm-4.5-air:free --output-dir devops_multi_agents/outputs/llm-benchmark --strict-security-tools --skip-image-scan

# CI/CD-only comparison
python -m devops_multi_agents.run_cicd_model_benchmark --repo gestion_stock --cicd-provider github --cicd-llm-provider ollama --cicd-model-a <model-a> --cicd-model-b <model-b> --cicd-judge-model <judge>

# DevSecOps-only comparison
python -m devops_multi_agents.run_devsecops_model_benchmark --repo gestion_stock --arch devops_multi_agents/outputs/architecture-analysis.json --model-a <m1> --model-b <m2> --judge-model <judge>
```

## Architecture

### Module Structure

```
application/
├── shared/                    # Base classes and utilities for all agents
├── devops_multi_agents/       # Main multi-agent module
│   ├── agents/                # Individual agent implementations
│   ├── orchestrator.py        # Workflow coordinator
│   ├── llm_judge.py           # LLM-as-judge for model comparison
│   ├── run_workflow.py        # Full workflow entry point
│   └── run_*.py               # Individual/benchmark entry points
└── .github/workflows/         # Example CI/CD pipelines (generated by the system)
```

### Shared Foundation (`shared/`)

- **`base_agent.py`** — `BaseAgent` abstract class all agents inherit from; defines `run()` interface and `AgentResult` dataclass
- **`common_models.py`** — Shared dataclasses: `AgentType`, `ServiceInfo`, `ProtocolType` enum (MCP, ACP, A2A, HYBRID_MCP_ACP)
- **`llm_common.py`** — LLM provider resolution, API key management, model selection from env vars
- **`utils.py`** — JSON I/O, `setup_logging` (also loads `.env`), output sanitization

### Agent Protocols

Each agent uses a specific communication protocol:
- **MCP** (Model Context Protocol): Local file/tool analysis — Architecture Analysis, DevSecOps Security
- **ACP** (Agent Command Protocol): LLM-driven generation — CI/CD Generation
- **A2A** (Agent-to-Agent Protocol): Derives from prior agent outputs — Chaos Engineering, Deployment
- **Hybrid MCP+ACP**: Combined — Incident Response

### Agent Pipeline (Execution Order)

```
Repository → Architecture Analysis → CI/CD Generation → DevSecOps Security
           → Deployment Planning → Chaos Engineering → Incident Response
           → Workflow Summary
```

Each agent reads JSON output from earlier stages and produces its own JSON output in `devops_multi_agents/outputs/`.

### Key Agent Details

**Architecture Analysis** (`agents/architecture_analysis_agent/`): Scans repo files to detect tech stacks, extract dependencies/ports/database connections, builds a dependency graph, and optionally generates LLM insights. Outputs a Mermaid diagram.

**DevSecOps Security** (`agents/devsecops_security/`): Runs Dockerized security tools (requires Docker daemon):
- `aquasec/trivy:0.57.1` — filesystem & image vulnerability scanning
- `zricethezav/gitleaks:v8.24.2` — secrets detection
- `bridgecrew/checkov:3.2.368` — IaC scanning

Docker images are configurable via `DEVSECOPS_TRIVY_IMAGE`, `DEVSECOPS_GITLEAKS_IMAGE`, `DEVSECOPS_CHECKOV_IMAGE`.

**CI/CD Generation** (`agents/cicd_generation_agent.py`): Generates provider-specific pipelines. Supported providers: `github`, `gitlab`, `azure-devops`, `bitbucket`. Interactively prompts if `--provider` is omitted.

**Deployment** (`agents/deployment/`): Generates Terraform (AWS/Azure/GCP) or Docker Compose (local/minikube) — target via `--target-env`. Integrates MongoDB state storage and Vault secrets management.

**Orchestrator** (`orchestrator.py`): Sequences all agents, handles git add/commit/push for CI/CD pipeline files, supports model comparison via `LLMJudge`.

## LLM Configuration

Set in `.env`:
```
LLM_PROVIDER=openrouter|groq|ollama    # Global default
OPENROUTER_API_KEY=...
OPENROUTER_MODEL=z-ai/glm-4.5-air:free
GROQ_API_KEY=...
GROQ_MODEL=llama-3.1-8b-instant
OLLAMA_BASE_URL=http://localhost:11434/v1

# Per-component overrides
ARCH_LLM_PROVIDER=...
DEVSECOPS_LLM_PROVIDER=...
JUDGE_LLM_PROVIDER=...
DEVSECOPS_LLM_TEMPERATURE=0.7
```

Ollama uses OpenAI-compatible mode — always set `OLLAMA_BASE_URL` with `/v1` suffix.
